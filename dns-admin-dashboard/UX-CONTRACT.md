# 관리자 검토 동작

시각 규칙은 DESIGN.md를 따른다. 현재 사용자 요청을 상태 의미와 화면 동작의 기준으로 사용한다.

## 상태와 결정

검토 메뉴는 불러온 항목 중 status=review만 표시한다. 전체 현황은 모든 상태를 조회하며 기존 보고서 모달에는 결정 버튼을 표시하지 않는다. review 항목의 보고서를 성공적으로 읽은 뒤 차단 또는 허용을 결정한다. 차단은 blocked, 허용은 allow로 저장한다. blocked는 RPZ 적용 완료를 의미하지 않는다.

## 공통 동작 소유자

| 기능 | 구현 위치 | 검증 |
|---|---|---|
| 목록 선택 | public/app.js의 renderReviews, openReview | 브라우저 선택 및 메뉴 전환을 확인한다. |
| Select/Listbox | native: 기존 네이티브 select | 기존 전체 현황 필터를 유지한다. |
| 시각 | public/app.js의 date | ko-KR, Asia/Seoul로 표시한다. |
| 보고서 | reportContent | 전체 현황과 검토 화면이 같은 함수를 사용한다. |
| 확인과 오류 | 네이티브 dialog, decision-error | 실패 시 확인창과 선택을 유지한다. |
| 결과 알림 | review-notice의 role=status | 저장 성공 후 결과를 표시한다. |
| 스크롤 | public/style.css | 데스크톱과 모바일 배치를 확인한다. |
| 상태 변경 | PATCH /api/decision, store.decide | 조건부 갱신과 충돌 거절을 테스트한다. |

## 저장과 충돌

확인창에는 대상 도메인과 변경 내용을 표시한다. 저장 중 중복 클릭, 메뉴 전환, 목록 갱신과 확인창 닫기를 막는다. 서버는 기존 관리자 인증과 요청 보호 헤더를 검증한다. status, created_at, updated_at, report_s3_key가 보고서 조회 시점과 일치하고 status=review인 항목만 조건부 갱신한다. DynamoDB의 status와 updated_at만 갱신한다. S3 보고서와 RPZ는 수정하지 않는다.

성공 후 목록의 상태를 갱신하고 검토 선택을 해제한다. 다음 항목을 자동으로 선택하지 않는다. 일반 오류에서는 선택과 보고서를 보존하여 재시도를 허용한다. 충돌이나 항목 삭제가 확인되면 저장을 막고 새로고침을 안내한다. 보고서 응답에는 요청 번호를 적용하여 늦게 도착한 이전 응답이 현재 선택을 덮어쓰지 못하게 한다.

## 자료 범위와 접근성

목록은 기존 Scan 페이지와 더 불러오기 방식을 유지한다. 검색, 집계와 검토 목록은 불러온 자료만 대상으로 하며 전체 review 건수를 의미하지 않는다. 보고서 없는 항목은 조회 오류와 재시도를 표시한다. collected_data=null인 수집 실패 보고서도 표시한다. 한글 도메인은 저장된 문자열을 그대로 키로 사용한다.

버튼은 네이티브 button으로 키보드 조작과 focus-visible 표시를 지원한다. 확인창은 네이티브 dialog의 포커스 이동과 Escape 동작을 사용한다. 저장 중 취소는 막는다. 성공 후 검색창으로 포커스를 이동한다.

기존 삭제 폼은 브라우저의 required 검사와 도메인 일치 검사를 함께 사용하는 native 검증을 유지한다. 정적 감사 도구는 별도 JS 파일의 addEventListener 연결을 인식하지 못할 수 있으므로 버튼 동작은 실제 브라우저 테스트를 근거로 확인한다.
