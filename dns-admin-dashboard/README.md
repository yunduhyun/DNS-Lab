# Express DNS 관리자 대시보드 MVP

## 1. 구현 범위

관리자가 도메인 목록과 분석 보고서를 조회하는 초기 MVP다. Express가 DynamoDB와 S3를 조회하고, 브라우저는 Express API를 통해 결과를 표시한다. 프런트엔드는 별도 빌드 없이 HTML, CSS, JavaScript로 구성한다.

- 관리자 HTTP Basic 인증을 적용한다. 브라우저 기본 인증 창에서 로그인한다.
- 도메인 현황과 검토 대상 화면을 제공한다.
- 도메인 검색, 상태 필터, 새로고침, 다음 페이지 불러오기를 제공한다.
- 확인 버튼을 누르면 모달을 열어 선택한 보고서의 AI 분석 본문, DNS 정보, 페이지 제목, 최종 URL, 본문, 링크, 폼, 헤더를 표시한다.
- 로그인 실패 횟수를 제한하고, 응답 캐시를 금지한다.
- 수집 자료는 textContent로 표시하며 HTML과 스크립트를 실행하지 않는다. 링크도 자동으로 접속하지 않는다.

차단 승인, 허용 결정, RPZ 반영, 평판 API 조회, 사용자 계정 관리 기능은 아직 구현하지 않는다. 위험 점수는 현재 보고서 형식에 없으므로 임의로 생성하지 않는다.

## 2. 파일 구성

```text
dns-admin-dashboard/
├── server.js              # 환경 설정과 서버 시작
├── app.js                 # 관리자 인증과 API 라우트
├── store.js               # DynamoDB와 S3 조회 및 샘플 자료
├── public/
│   ├── index.html         # 화면 구조
│   ├── style.css          # 화면 스타일과 반응형 배치
│   └── app.js             # API 호출과 안전한 텍스트 표시
├── test/                 # 인증, API, 저장소, 모달 흐름 검증
├── ec2-read-policy.json   # EC2 IAM 역할에 추가할 읽기 권한 예시
├── .env.example          # 환경변수 예시
├── package.json
└── README.md
```

## 3. 로컬 실행

Node.js 22 이상을 사용한다. 터미널에서 프로젝트 폴더로 이동한 뒤 다음 명령을 실행한다.

```bash
npm ci
cp .env.example .env
```

`.env`의 `ADMIN_PASSWORD`를 직접 정한 12자 이상의 비밀번호로 변경한다. `.env`는 비밀 파일이며 Git에 등록하지 않는다. 기본 실행 주소는 `127.0.0.1:3000`이다.

```bash
npm start
```

브라우저에서 `http://127.0.0.1:3000`에 접속한다. 사용자명은 기본값 `admin`이며 비밀번호는 `.env`에 지정한 값이다. 비밀번호가 비어 있거나 짧으면 서버가 시작하지 않는다.

`DATA_MODE=demo`에서는 화면 확인용 자료만 사용한다. 실제 AWS를 호출하지 않으며 샘플 표시를 화면에 명시한다. 검토 대상으로 표시한 샘플도 실제 분석 결과가 아니다.

테스트는 다음 명령으로 실행한다.

```bash
npm test
```

## 4. 실제 AWS 연결

`.env`에서 다음 값을 설정한다.

```text
DATA_MODE=aws
AWS_REGION=ap-northeast-2
DYNAMODB_TABLE=dns-domain-analysis
S3_BUCKET=dns-analysis-reports-994899741506-ap-northeast-2-an
```

로컬에서 AWS를 조회할 때만 `AWS_PROFILE=dns-project`를 설정한다. 로컬 사용자에게도 읽기 권한이 필요하며, 기존 쓰기 권한만으로 조회할 수는 없다.

EC2에서는 IAM 역할을 연결하고 `AWS_PROFILE`과 고정 액세스 키 환경변수를 제거한다. SDK가 인스턴스 역할의 임시 자격증명을 사용한다. `ec2-read-policy.json`은 현재 코드에 설정한 테이블과 버킷을 기준으로 만든 예시다. 실제 자원 이름을 확인하고 해당 역할에 추가한다. 이 프로젝트는 IAM을 자동으로 수정하지 않는다.

S3 기본 SSE-S3 암호화를 가정한다. 별도 KMS 키를 사용한 버킷은 키 정책과 `kms:Decrypt` 권한을 추가 확인해야 한다. EC2에서 DynamoDB 및 S3 엔드포인트로 연결 가능한 네트워크 경로가 필요하다.

## 5. DynamoDB와 S3의 연결

목록은 DynamoDB의 domain, created_at, report_s3_key, status, updated_at을 읽는다. 표는 해당 순서와 보고서 확인 버튼으로 구성한다. 생성 및 갱신 시각은 한국 시간으로 표시하며, 긴 보고서 키는 말줄임 표시하고 마우스를 올리면 전체 경로를 확인할 수 있다. 확인 버튼을 누르면 페이지 위에 모달이 열리며 로딩 상태를 먼저 표시한다. 이어서 DynamoDB에서 해당 도메인을 다시 조회하고 저장된 키로 S3 객체를 읽는다. S3 객체 키를 브라우저에서 직접 입력받지 않는다.

```text
관리자 → Express → DynamoDB 도메인 조회
                  → report_s3_key 확인
                  → S3 JSON 보고서 읽기
                  → 화면에 텍스트 표시
```

필요한 DynamoDB 항목 예시는 다음과 같다.

```json
{
  "domain": "example.com",
  "status": "Analyzing",
  "updated_at": "2026-10-25T00:00:00+00:00",
  "report_s3_key": "reports/example.com/작업ID.json"
}
```

현재 Python 프로그램이 report_s3_key를 아직 기록하지 않는 경우, 보고서 파일이 S3에 있어도 화면에는 보고서 위치 미등록으로 표시한다. Python의 S3 업로드 성공 직후 해당 키를 DynamoDB에 기록하는 연결 작업이 필요하다. 대시보드는 이 값을 추측하거나 기존 Python 코드를 수정하지 않는다.

모달은 닫기 버튼, Escape 키, 배경 클릭으로 닫는다. 모달을 열면 내부로 키보드 포커스가 이동하고, 닫으면 확인 버튼으로 돌아간다. 모달을 닫은 뒤 늦게 도착한 응답은 표시하지 않는다. 조회 오류도 모달 안에 표시한다.

보고서 형식은 현재 Python 출력과 동일하게 domain, job_id, analyzed_at, collected_data, analysis를 사용한다. 최대 5MB까지 읽으며 JSON 해석 실패나 도메인 불일치는 안내 메시지로 처리한다.

## 6. 페이지와 상태

목록은 한 번에 최대 50개를 Scan으로 읽는다. 더 불러오기 버튼으로 다음 페이지를 조회한다. 검색과 필터, 상단 집계는 불러온 목록에만 적용한다. Scan 결과의 시각순 정렬은 보장하지 않는다. 규모가 커지면 상태 및 시각 기준 GSI로 변경한다.

검토 대상 화면은 status가 review인 항목을 표시한다. AI 보고서가 존재한다는 이유만으로 review 상태를 부여하지 않는다. 상태 결정은 별도의 분석 정책에서 처리한다.

시각은 한국 시간으로 표시한다. 조회 중, 결과 없음, 보고서 위치 미등록, 권한 오류, 잘못된 보고서에 대한 안내를 제공한다. 새로고침은 목록을 다시 읽으며 보고서는 선택 시 다시 읽는다.

## 7. EC2 실행 시 확인 사항

초기에는 기본 로컬 바인딩을 유지하고 SSH 터널을 통해 접속할 수 있다. SSH를 사용하는 환경의 예시는 다음과 같다.

```bash
ssh -i /path/to/key.pem -L 3000:127.0.0.1:3000 ec2-user@EC2주소
```

SSH 사용자명은 AMI에 맞게 변경한다. 접속 후 로컬 브라우저의 `http://127.0.0.1:3000`을 사용한다. 보안 그룹에 3000번 포트를 외부 공개할 필요는 없다.

관리자에게 외부 공개할 때는 HTTPS 리버스 프록시 또는 HTTPS ALB를 먼저 구성한다. HTTP Basic 인증은 전송 암호화를 제공하지 않으므로 외부 HTTP 연결로 사용하지 않는다. 현재 Helmet의 HSTS와 HTTPS 강제 전환은 로컬 HTTP 검증을 위해 비활성화되어 있으며, 외부 배포 시 TLS 구성과 함께 조정한다.

기본 인증은 브라우저가 자격증명을 기억하므로 명시적인 로그아웃을 제공하지 않는다. 공유 기기 사용과 다중 관리자 운영 단계에서는 세션 인증으로 전환한다. 현재 로그인 제한은 프로세스 메모리에 저장하며 재시작 시 초기화된다. 프록시 설정을 변경할 때는 신뢰할 프록시 범위와 클라이언트 IP 판별을 함께 검토한다.

## 8. 검증 범위

자동 검증은 샘플 저장소 및 대체 응답을 사용한다. 실제 AWS 권한과 S3 보고서 읽기, EC2 배포는 사용자가 구성한 환경에서 별도로 확인한다. 실제 AWS 자원과 DNS 정책은 이 작업에서 변경하지 않는다.

자동 테스트 7개와 JavaScript 구문 검사를 통과했다. 모달 검사는 DOM 대체 객체로 로딩, 보고서 표시, 오류 표시, 닫기, 포커스 복원, 늦은 응답 무효화를 확인한다. Escape 키와 포커스 가두기는 네이티브 dialog 기능을 사용하며 실제 브라우저에서 별도 확인이 필요하다. 브라우저 자동 제어가 앱 설정에서 비활성화되어 있어 실제 화면 렌더링과 클릭 동작은 확인하지 못했다. 로컬 HTTP 테스트로 인증, 정적 HTML 제공, API 응답을 확인했다.
